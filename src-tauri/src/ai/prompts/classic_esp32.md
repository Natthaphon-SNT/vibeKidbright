### CLASSIC ESP32 HOST RULES
Use ESP-IDF C for the confirmed classic KidBright/ESP32 board. Never generate Arduino setup/loop/Wire code as firmware. Verify the resolved SDK APIs and include headers/declarations for every API used. Use FreeRTOS delays with the proper headers and avoid unused constants or misleading indentation. Current executable profiles: kidbright32_v13 and kidbright32_rev31. button_buzzer, temperature_serial and music_scale are scoped recipes; matrix_counter is v1.3-only. Missing profiles allow a custom reviewed draft without substituting another model.

### RETRIEVE PERIPHERAL RULES ON DEMAND
- Read the matching kidbright32_v13.md, kidbright32_v15.md, kidbright32_versions.md or inex_ia_ip.md when needed. Exact revision is required only if a known difference affects the task. Do not assume iA as a default. Do not confuse Formula Kid Controller with Controller V1/minibike.
- Full classic examples/rules are in guides/classic_esp32.md; retrieve only the section needed. For behavior matching call kidbright_reference: no arguments returns a compact index, catalog_board selects exact board details, and board_profile/reference_example selects a recipe. Catalog entries are not executable profiles.
- Matrix: use led_16x8_matrix_mapping.md and exact task evidence. Do not impose one orientation/interleaving/inversion across revisions. Preserve the user-reported iP A-Z display source for that task; no physical certification of other peripherals follows.
- I2C: preserve confirmed wiring and a single driver family for the whole app; do not mix driver/i2c.h and driver/i2c_master.h. Reuse initialized shared bus handles and mutexes; do not infer controller IDs from connector labels. For supplied v1.3/v1.5 designs, matrix SDA21/SCL22 differs from LM73/RTC/Chain SDA4/SCL5; these are not universal defaults.
- ADC: distinguish onboard LDR from external connector capability. v1.3 IN1-4 are buffered digital; v1.5 analog paths depend on actual bypass assembly. GPIO34-39 are input-only without internal pull resistors; GPIO18/19/23 lack ADC/DAC. Use the SDK-supported oneshot/calibration APIs; raw values are not lux or calibrated volts.
- Outputs: distinguish gate GPIO/JST from MOSFET drain/banana endpoints. Do not infer DAC at banana OUT or USB-host data from a power-controlled USB-A connector. Servo wiring/power is revision-specific.
- ESP-NOW: read matching peer references before writing. Preserve actual ASCII or custom binary_int32 framing, timing and length checks. WiFi task callbacks are not hardware ISRs; enqueue without blocking, never use FromISR solely because this is a callback. Do not assume fields from another IDF callback version.
- Motor/servo/OLED/accelerometer: retrieve device-specific KB files and exact SDK headers; never borrow pins/protocols from another controller. Original Arduino/simulator code is reference data requiring an explicit C port. Select OLED/controller/address/driver family and initialization order from exact evidence.

### C PROJECT AND BUILD
Register all source/component dependencies in CMake. Preserve sdkconfig, target and build cache for ordinary incremental edits; never set-target/fullclean/delete build to fix a source-only error. Inspect exact diagnostics and related sources/configuration before repairs. After Keep, use the configured authorized build route; build success is not physical success. No automatic Flash or indefinite monitor.
