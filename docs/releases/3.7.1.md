# VibeKidbright IDE 3.7.1 — Classic KidBright hotfix

สร้างจากซอร์ส 3.7.0 ที่ผู้ใช้แนบ ซึ่งตรงกับ tag `v3.7.0` (`a593b0d4956a08ac711f60184aa6d62ff30f7304`) ทุกไฟล์ สายแก้ไขอยู่ที่ `hotfix/3.7.1` แยกจากโค้ดพัฒนาปัจจุบัน 3.7.4

- คง auto-install toolchain แต่ส่งสถานะพร้อมหลังย้ายโฟลเดอร์และซ่อม Python path ที่ตำแหน่งติดตั้งจริงแล้ว แทนการชี้ `.installing` และรอการเปิดโปรแกรมใหม่มาซ่อม
- Refresh/repair/install ล้าง SDK/PATH cache และ AI ใช้ตัวค้นหา SDK เดียวกับ Build/Terminal จึงมองเห็น managed toolchain ใน session เดียวกัน
- คำขอสร้างโปรเจกต์ใหม่ต้องเลือก workspace ใหม่ แม้โปรเจกต์เดิมยังเปิดอยู่ ถ้ายกเลิกหรือชื่อโฟลเดอร์ซ้ำจะไม่กลับไปเขียนโปรเจกต์เดิม
- ปรับ system prompt และข้อมูล V1.3/V1.5/INEX ตามหลักฐานล่าสุด แยก GPIO/connector, analog path และ LED/Servo ตามรุ่น ไม่อ้าง GPIO4 เป็น BT LED จากตารางทั่วไป
- รุ่นนี้มีเฉพาะตัวเลือก classic KidBright ไม่มีคำสั่ง ADB, learning workspace หรือ deployment ของ µAI/µAI Plus

การทดสอบใช้ unit tests, filesystem fixtures และ browser ที่จำลอง native IPC ไม่มีการเรียกโมเดลที่เสียค่าใช้จ่าย ไม่มีการดาวน์โหลด/ติดตั้ง toolchain ขนาดใหญ่ลง AppData จริง และไม่มีการ flash บอร์ดหรือรัน installer ทับแอปผู้ใช้ ผลที่รายงานจึงเป็น software validation ไม่ใช่ผลทดสอบบอร์ดหรือเครื่องผู้ใช้

ก่อนเผยแพร่ ทดสอบ installer บนเครื่องหรือ Windows Sandbox แยก โดยเริ่มจาก 3.7.0, ปล่อย auto-install ให้เสร็จ แล้วตรวจ Build/Terminal/AI โดยไม่ปิดแอป จากนั้นเปิดโปรเจกต์ A และสั่งสร้างโปรเจกต์ B ยืนยันว่าไฟล์ A ไม่ถูกแก้ รวมเคสยกเลิกเลือกโฟลเดอร์และชื่อ B ซ้ำ

Release นี้เป็น hotfix สำหรับผู้ใช้ 3.7.0 ไม่ใช่การลดเวอร์ชันของผู้ใช้ 3.7.3/3.7.4 และไม่ควรแทนป้าย Latest ของสายใหม่ workflow แยกตั้ง `make_latest: false` และสร้าง draft ก่อน ตาม [GitHub release documentation](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository) และ [action-gh-release](https://github.com/softprops/action-gh-release)
