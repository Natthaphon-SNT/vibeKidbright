# พรอมท์เทส mAi Plus + IPST MicroBOX 4.0 — Sensors and Actuators

ชุดนี้จัดตาม **รายการอุปกรณ์ที่ผู้ใช้ยืนยัน** และหมวด Sensors and Actuators หน้า PDF 59–79 ของเอกสารอังกฤษ 151 หน้า ควบคุมด้วย **mAi Plus SG2002 / MaixPy 4** ต่ออุปกรณ์ผ่าน **iKB-1 ที่มีจริง** ไม่สลับเป็น IPST-WiFi หรือ iKB-1Z โดยอัตโนมัติ

มี **64 เทส: 62 เทสสำหรับชุดที่แจ้ง + 2 เทสพัดลม/ปั๊มแบบมีเงื่อนไขตาม PDF** ตรวจข้อกำหนดและ API จากซอร์สแล้ว แต่ยังไม่ได้ให้โมเดลสร้าง/รันครบ 64 โปรแกรมหรือทดสอบโหลดจริง ไม่มีเทสใดได้ hardware PASS ล่วงหน้า

## จุดที่ปรับจากภาพ/ตัวอย่างในหนังสือ

- ภาพหน้า 59 เป็นภาพประกอบ ไม่ใช้ระบุรุ่นเซนเซอร์ รายการจริงมี ZX-Sonar **แอนะล็อก** จึงไม่ใช้โค้ด TRIG/ECHO ของ HC-SR04 และไม่เพิ่ม DHT เป็นอุปกรณ์ในกล่องนี้
- หน้า 67–70 ใช้ชื่อ PH13/PH14 และยกตัวอย่าง polarity; ไม่คัดเป็นขา SG2002 หรือกำหนด active level โดยไม่วัด
- หน้า 68 ตั้งหัวข้อ ANALOG แต่ภาพบล็อกอ่าน digital pin: ZX-03 ในชุดจริงให้ใช้เส้นทาง **analog ผ่าน iKB** และคาลิเบรตดำ/ขาว
- ADC0 ของ mAi Plus ใช้ปุ่ม S1/S2; ADC ช่อง 0 ของ iKB เป็นคนละอุปกรณ์ ช่วงปุ่มที่เพิ่งวัดไม่ใช่ threshold ของ ZX-POTV/เซนเซอร์ภายนอก
- หน้า 73–78 อธิบาย iKB-1Z แต่รายการที่ผู้ใช้ส่งเป็น iKB-1 ให้ยืนยัน label/firmware/connector รุ่นจริงก่อนใช้ driver สำหรับตระกูลนี้
- ตัวเลข 10–15 ที่ silk ของ iKB เป็นช่อง servo 1–6 ตามรูปหน้า 78 ไม่ใช่ Plus IO7; มอเตอร์ที่มี driver บนบอร์ดใช้ M1/M2 ไม่เหมารวม output3/4
- Catalog เขียน MCP9731; ยังไม่เปลี่ยนชื่อชิปเอง เทส raw ทำก่อน องศาเซลเซียสต้องตรงรหัสจริงและ datasheet
- ZX-RGB12R เป็น WS2812 และ ZX-SPEAKER ต้องมี backend สร้าง waveform/tone จริง การมีอุปกรณ์แล้วไม่พิสูจน์ว่ามี driver บน Linux ติดตั้งอยู่
- ชุด BO1 “2 Output” ไม่พิสูจน์ว่ามีมอเตอร์อิสระสองตัว; ตรวจจำนวนก่อนเทสหุ่นยนต์
- iKB เป็น MCU ภายนอก โปรแกรมบน Plus หยุดแล้ว output อาจยังคงค่า โดยเฉพาะกรณี forced kill/สายสื่อสารขาด อย่าให้ finally เป็นหลักฐานว่าโหลดดับแล้ว

## ผังเดี่ยวสำหรับเริ่มทดสอบ

## วิธีใช้

ส่งพรอมท์ตั้งต้นด้านล่างครั้งแรก จากนั้นส่งรายข้อทีละข้อ ใช้ชื่อ `mai_sa_001` เป็นต้น หากโฟลเดอร์มีแล้ว ให้เสนอชื่อใหม่ที่ยังไม่มีและคงรายละเอียดงานเดิมเมื่อผู้ใช้ตอบรับชื่อใหม่ ผู้ทดสอบกด Keep/Connect/Run/Stop เอง

**SA-xxx เป็นรหัสใน log/รายงาน ไม่ใช่ค่า native `test_id` ซึ่งรองรับเฉพาะ MP-001–128** จึงไม่ส่ง `test_id="SA-xxx"` ไปเครื่องมือสร้างโปรเจกต์

```text
ใช้ mAi Plus SG2002, MaixPy 4.12.5 / Runtime 1.24.0 เป็น baseline ตามข้อมูลบอร์ดเดิม ฉันมีอุปกรณ์ตาม IPST MicroBOX 4.0 แล้ว ไม่ต้องถามซ้ำว่ามีอุปกรณ์หรือไม่ บอร์ดหลักยังเป็น mAi Plus ไม่เปลี่ยนไปโปรแกรม IPST-WiFi หรือ flash firmware เอง

สำหรับ SA-xxx สร้างโปรเจกต์ใหม่ชื่อที่ระบุด้วย project_type="kidbright_uai_plus" และส่ง main_python เป็นโค้ด main/main.py ที่ทำเทสนั้นจริงให้ครบตั้งแต่คำสั่งสร้าง ไม่ส่ง test_id="SA-xxx" และไม่สร้างวงกลมหรือ seed MP-021 แล้วขอ Keep ก่อนเริ่มเขียนงาน ขอ Keep เมื่อโค้ดที่ขอและ helper proposals ครบแล้วเท่านั้น write_file เสนอไฟล์เพิ่มได้ระหว่าง creation review

จัด CONFIG ของ bus/address/channel/รุ่นโมดูล/ไฟเลี้ยง/ขอบเขตโหลดไว้ต้นโปรแกรม ตั้ง DRY_RUN=True และ ARMED=False สำหรับ output ก่อนทดสอบแยกแล้วให้ผู้ทดสอบเลือก START ที่จอหรือปรับค่า ARM ใน CONFIG เมื่อพร้อมจริง ไม่มีการ run บอร์ดอัตโนมัติ ขั้นที่ข้อมูลยังขาดให้สร้างหน้าตรวจและบอกค่าที่ขาดตรงจุด ไม่เดาว่าอุปกรณ์หาย

จอใช้ from maix import app,display,image,time; Display.width/height, image.Image(...,image.Format.FMT_RGB888), draw_rect/draw_string/show, close และ loop while not app.need_exit() ทัชใช้ maix.touchscreen.TouchScreen/read()->[x,y,pressed]/close แยก pressed edge
IMU ใช้ from maix.ext_dev import imu; imu.IMU("qmi8658",mode=imu.Mode.DUAL); read() ตรวจหกแกนและหน่วยก่อนใช้ ห้าม index อุณหภูมิที่เจ็ดโดยเดา
I2C ใช้ from maix import i2c; i2c.list_devices(); i2c.I2C(id,i2c.Mode.MASTER,freq=100000); writeto(addr,bytes), readfrom(addr,n) ตรวจ write length/negative error และ None/short read ไม่แต่ง timeout keyword หรือ close ที่ไม่มี
ซอร์ส Plus มี software I2C bus5 บน A28/A29 แต่ต้องมี node/backend และ wiring ยืนยันก่อน ถ้าไม่มีให้ NEEDS_BACKEND ไม่ insmod ไม่แก้ pinmux/boot script และไม่ import iKB1 ของ upstream ซึ่งมี side effect

ให้สร้าง main/ikb_adapter.py เป็น adapter ของโปรเจกต์เองโดยอิง packet contract ที่อ่านจากซอร์ส iKB1/iKB1_uAiP:
- bus และ address รับจาก CONFIG หลังตรวจ ไม่เปิด bus ตอน import; address ตาม board/jumper ไม่ scan 0x48 แล้วถือว่าเป็น iKB ทันที
- digital read ช่อง0..7: ส่ง bytes([0x08+ch,2]) (หรือ3เมื่อเลือกpull-upจริง) แล้วอ่าน1byte ตรวจว่าเป็น0/1; การอ่านนี้มีการตั้งโหมดinput ไม่ใช่passive probe
- digital write ช่อง0..7: ส่ง bytes([0x08+ch,0หรือ1]); ห้ามเปลี่ยนช่องที่มีanalog sensorเป็นoutput
- analog read ช่อง0..7: ส่ง bytes([0x80+(ch<<4)]) รอตาม protocol ตัวอย่าง0.1s แล้วอ่าน2byte big-endian; ตรวจช่วงที่โหมดADC10bitรองรับ ไม่ยืม4095ของADC12bit
- motor เฉพาะM1/M2: packet [0x20 | (1<<(channel-1)), encoded_speed] โดย signed speed percent -100..100; encoded_speed= signed_speed & 0xff; stop=0 เสมอ ไม่ให้reverse0กลายเป็นbyte256
- servo ช่อง1..6: packet [0x40 | (1<<(channel-1)), angle] โดยangleต้องเป็นจำนวนเต็มในขอบเขตSG92R/กลไกที่ผู้ทดสอบยืนยัน ไม่เริ่มที่0อัตโนมัติ ไม่ส่งreset([0x00])ทุกครั้งที่เลือกaddress ไม่มีservo-disable commandที่ยืนยันในcontractนี้
ชื่อ ikb_adapter.py และเมธอดที่สร้างเป็น API ของโปรเจกต์ ไม่ใช่ built-in MaixPy ที่อ้างว่าติดตั้งอยู่แล้ว อย่า copy side effects ของ upstream library; native readfrom ไม่มี timeout ที่รับประกันและiKBอาจคงoutputเมื่อprocessตาย

ใช้ bus handle เดียว จัดลำดับ transaction และบันทึก effective sample interval จริง ไม่อ้างความเร็ว sampling ที่ I2C/ADC ทำไม่ได้ เก็บ buffer/log/file แบบมีขอบเขต อ่านล้มเป็น ERROR ไม่ใช่ค่าปกติ0 ไม่แปลง raw เป็น lux/dB SPL/ความชื้น%/องศา/cm จนมีสูตรและreferenceตรงรุ่น

ทุก output มีขอบเขต/เวลา/สถานะก่อน START และ cleanup ตาม API จริง ระบุสถานะส่งคำสั่งกับผลทางกายภาพแยกกัน โปรแกรมไม่ควบคุม Launcherเอง ข้อมูลfresh/stale/errorต้องเห็นชัด ผลเริ่มNOT_RUNหรือWAIT_USER ห้ามให้PASSจากcompile/upload/dry-runเพียงอย่างเดียว
```
