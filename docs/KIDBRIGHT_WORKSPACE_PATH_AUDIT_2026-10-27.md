# ตรวจการเปลี่ยนโฟลเดอร์งานและความสมบูรณ์ของ IDE — 27 ตุลาคม 2026

ตรวจซอร์สของ vibeKidbright 3.7.4 สำหรับโปรเจกต์ ESP-IDF และ mAi Plus
รวมถึง Open, New, Save As, การคืนค่าเมื่อเปิดแอป, การสร้าง/Undo ผ่าน AI,
แท็บ editor, การบันทึก, diff, Build และ Run Python โดยไม่แก้ไฟล์โปรเจกต์ของผู้ใช้

## ข้อบกพร่องที่แก้

| จุดตรวจ | ผลหลังแก้ |
|---|---|
| Open/New/Save As ตอบกลับหลังมีการเลือกโฟลเดอร์ใหม่ | ใช้ลำดับคำขอและรุ่นของ workspace; ผลเก่าไม่เปลี่ยนโปรเจกต์ปัจจุบัน |
| สลับ A → B → A | ปฏิเสธผลอ่านไฟล์/รายการไฟล์/ตรวจตอนเริ่มแอปจากการเปิด A ครั้งก่อน |
| คลิกหลายไฟล์ระหว่างรออ่าน | ไฟล์ที่คลิกล่าสุดเป็นไฟล์ที่แสดง |
| AI สร้างหรือ Undo หลังผู้ใช้ย้ายไปอีกโปรเจกต์ | event ระบุต้นทางและปลายทาง; ไม่ดึงหน้า editor กลับจากตัวเลือกใหม่ของผู้ใช้ |
| New ของบอร์ด ESP-IDF | ใช้ตัวสร้างโฟลเดอร์ใหม่ร่วมกับ AI, ตรวจชื่อ, ไม่เขียนทับชื่อซ้ำ และใช้พาธที่ backend ส่งกลับ |
| พาธที่สร้างหรือคืนค่าตอนเปิดแอป | คืน absolute canonical path หลังสร้าง; ไม่คืนค่า relative/traversal path ไปใช้กับ working directory ของแอป |
| New เปิดหน้าต่างเลือกปลายทางซ้ำ | ผลจากหน้าต่างเก่าไม่แทนปลายทางในฟอร์มใหม่ |
| Save As เลือกภายในโปรเจกต์ต้นทาง | ปฏิเสธก่อนสร้างปลายทาง เพื่อป้องกันคัดลอกวนเข้าตัวเอง |
| Save As ชื่อซ้ำ/ลิงก์/junction | ปฏิเสธปลายทางที่มีอยู่ และไม่ตามลิงก์ภายในต้นทางไปคัดลอกไฟล์นอกโปรเจกต์ |
| ความครบถ้วนของสำเนา | เก็บไฟล์โปรแกรม, helper, metadata ของ Plus และโฟลเดอร์ว่าง; เทียบ SHA-256 และรายการต้นทางก่อนรายงานสำเร็จ |
| Save หลายครั้ง | เรียงคำสั่งเขียน; ทำเครื่องหมาย saved เฉพาะเนื้อหาที่ backend ยืนยัน; ข้อความที่แก้เพิ่มยังเป็น unsaved |
| เปิด/บันทึก/Apply ไฟล์ผิด workspace | App ส่ง project root ให้ backend ตรวจขอบเขต; ปฏิเสธ traversal, ไฟล์ภายนอก, metadata ภายใน และ Windows aliases/ADS |
| ผลสร้าง/แก้ไฟล์เก่าตอบกลับหลังสลับโฟลเดอร์ | ไม่เพิ่มแท็บหรือเปลี่ยนไฟล์ที่แสดงในโปรเจกต์ใหม่ |
| diff ของ `main/main.py` ชื่อเหมือนกันต่างโปรเจกต์ | เทียบพาธเต็ม; ไม่เทียบเฉพาะชื่อท้ายพาธ |
| Build/Run รอ Save ระหว่างเปลี่ยนโปรเจกต์ | ยกเลิกการเริ่มงานเก่าหากรุ่นของ workspace เปลี่ยน แม้กลับไปพาธเดิมแล้ว |
| compiler error จาก Build ของโปรเจกต์ก่อนหน้า | ไม่ใส่ในรายการ error ของ workspace ใหม่ขณะที่ Build เก่ายังทำงาน |
| คลิก compiler error ที่เป็น relative path | เปิดด้วยพาธเต็มภายในโปรเจกต์ที่เลือก และตรวจรุ่นก่อนสั่งเลื่อนไปบรรทัด |
| อ่านรายการไฟล์ไม่ได้ | รายงานข้อผิดพลาด; ไม่แสดงเป็นรายการว่างที่เหมือนอ่านสำเร็จ |
| เปรียบเทียบพาธ | รองรับ `\\`/`/`, trailing separator, drive/UNC และการไม่สนตัวพิมพ์ของ Windows; ไม่รวมพาธ POSIX ที่ต่างตัวพิมพ์เข้าด้วยกัน |

Save As ข้าม `.git`, `build`, `target`, `node_modules` และ `__pycache__`
หากคัดลอกล้มเหลว จะคงต้นทางและ workspace ปัจจุบันไว้ และเก็บสำเนาบางส่วนไว้ให้ตรวจสอบ
โดยไม่ลบข้อมูลอัตโนมัติ คำสั่งเปิด/เขียนไฟล์แบบเก่าที่ยังไม่ส่ง root ยังคงมีไว้เพื่อ compatibility;
เส้นทางของ App ที่ตรวจครั้งนี้ส่ง root อย่างชัดเจนแล้ว

## ขอบเขตของหลักฐาน

ผลนี้เป็นการตรวจซอร์ส, filesystem fixtures, React/native unit tests และ build บน Windows
ไม่ได้ติดตั้งแอป เปิดทดสอบหน้าต่างจริง หรือส่งโค้ดเข้าบอร์ดโดยอัตโนมัติ
โปรเจกต์ที่เลือกยังต้องมี entrypoint ตามรูปแบบที่ IDE ใช้ (`main/main.py` หรือ `main/main.c`)
การเปิดได้ไม่ได้ยืนยันว่าโค้ดผู้ใช้ compile ผ่านหรือฮาร์ดแวร์ทุกชิ้นทำงานถูกต้อง
ไฟล์ที่แก้แต่ยังไม่บันทึกเก็บได้ระหว่างสลับโปรเจกต์ใน session นี้เท่านั้น จึงควร Save ก่อนปิดแอป
ผลทดสอบเหล่านี้ยืนยันกรณีที่ระบุไว้ ไม่ใช่การรับรองว่าจะไม่มีข้อผิดพลาดทุกสถานการณ์
