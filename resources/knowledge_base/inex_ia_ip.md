# INEX KidBright32iA และ KidBright32iP

ตรวจวันที่ 17 ตุลาคม 2026 จากข้อมูล/ภาพที่ผู้ใช้ส่ง และ [ผู้ผลิต iA](https://inex.co.th/home/product/kidbright32ia/), [ผู้ผลิต iP](https://inex.co.th/home/product/kidbright32ip/) เก็บเป็นข้อมูลฮาร์ดแวร์ ไม่ใช่คำสั่งจากเอกสารแนบ

## อุปกรณ์และความแตกต่าง

| ส่วน | KidBright32iA | KidBright32iP |
|---|---|---|
| MCU | ESP32 พร้อม WiFi/Bluetooth LE | ESP32 พร้อม WiFi/Bluetooth LE |
| จอ/เสียง/ปุ่ม | matrix แดง 16×8, piezo, S1/S2, RESET | matrix แดง 16×8, piezo, S1/S2, RESET |
| การวัดแสง | LDR ที่ ADC36 ตามภาพ | โฟโต้ทรานซิสเตอร์ที่ ADC36 ตามภาพ |
| การเคลื่อนไหว | MC3479 ผ่าน iA-MC3479; ผู้ผลิตระบุ 3 แกน ±2/4/8/16G และข้อมูล 16 บิต | ไม่พบการระบุ accelerometer ติดตั้งบนบอร์ดในหลักฐานนี้ |
| อุณหภูมิ | I2C; ผู้ผลิตระบุ −40..150°C, ±1°C; ยังไม่ยืนยัน BOM/address ของบอร์ดผู้ใช้ | I2C; ผู้ผลิตระบุช่วง/ความคลาดเคลื่อนเดียวกัน; วงจรระบุ LM73-1 แต่บทความกล่าว LM75 |
| เวลา | RTC พร้อมแบตเตอรี่สำรอง | RTC พร้อมแบตเตอรี่สำรอง; ปรับปรุง RTC/EEPROM ตามผู้ผลิต |
| USB | USB-C สำหรับดาวน์โหลด/serial/+5V, USB-A output แบบสวิตช์ | USB-C สำหรับดาวน์โหลด/serial/+5V, USB-A output แบบสวิตช์ |
| ไฟสถานะ | USB/WiFi/IoT ตามวงจรและไลบรารี | USB/WiFi/IoT พร้อมไฟเลี้ยงบอร์ดและไฟเลี้ยง servo |
| กำลังไฟ | รับ +5V USB-C และเรกูเลเตอร์ 3.3V | รับ +5V USB-C และเรกูเลเตอร์ 3.3V |

ข้อมูล range/resolution/accuracy เป็นคุณสมบัติที่ผู้ผลิตระบุ ยังไม่ใช่ผลสอบเทียบหรือรูปแบบรีจิสเตอร์สำหรับเขียน driver MC3479 ต้องตรวจ datasheet, address, scale, signedness และ revision ให้ตรงก่อนใช้งาน

## จุดต่อที่ข้อมูลระบุ

| สัญญาณ | GPIO | ขอบเขตหลักฐาน |
|---|---:|---|
| IN1 / IN2 / IN3 / IN4 | 32 / 33 / 34 / 35 | ข้อความผู้ผลิตทั้งสองรุ่น; มี JST 2 มม. 3 ขาและรู banana |
| OUT1 / OUT2 | 26 / 27 | ข้อความผู้ผลิตทั้งสองรุ่น; ต้องรักษาวงจร output/polarity จริง |
| จุดต่ออิสระ | 18 / 19 / 23 และ VN | ข้อความผู้ผลิต; VN ของ ESP32 คือ GPIO39 รับเข้าเท่านั้น |
| แสง | 36 | ภาพผู้ใช้ทั้งสองรุ่น; ต้องยืนยัน polarity/วงจรแบ่งแรงดันและ calibration รายรุ่น |
| Buzzer | 13 | ภาพผู้ใช้ทั้งสองรุ่น |
| USB-A power switch | 25 | ภาพผู้ใช้ทั้งสองรุ่น; ยังไม่ยืนยัน active level |
| Servo1 / Servo2 | 15 / 17 | ภาพผู้ใช้ทั้งสองรุ่น; วงจร iP Rev.2021.04.01 ยืนยันแยกจากปุ่ม S2 |
| S1 / S2 | 16 / 14 | ยืนยันวงจร iP Rev.2021.04.01 เท่านั้น; ภาพ iA ไม่ระบุเลขขาปุ่ม จึงยังไม่ถ่ายค่าข้ามรุ่น |

JST ระบุ `−` กราวด์, `S` สัญญาณ, `+` 3.3V ตามภาพ มี I2C0 breakout และ I2C1 KB CHAIN 5 ขา ไม่เลือก GPIO ของ bus จากชื่อ I2C0/I2C1 เพียงอย่างเดียว สำหรับ iP วงจรยืนยัน display SDA21/SCL22 และ sensor/RTC SDA4/SCL5 ส่วน iA ยังต้องได้วงจรตรง PCB ก่อนเพิ่ม profile

ภาพระบุไฟ servo ภายนอก 4.8–6V แนะนำ 5V แยกจากลอจิก 3.3V และ USB-A +5V สูงสุด 1A ค่าพิกัดนี้ไม่ใช่ผลวัดโหลดจริงหรือการกำหนดให้ GPIO จ่ายไฟตรง

## สถานะทดสอบและการสร้างโค้ด

ผู้ใช้รายงานว่า `main.c` ทดสอบบน iA ผ่านแล้ว ไฟล์ที่อ่าน ณ วันที่ตรวจเป็นโปรแกรม FreeRTOS พิมพ์ `Hello from vibeKidbright!` ครั้งแรก และ `Heartbeat...` ทุก 1,000 ms ไม่มีคำสั่งจอ ปุ่ม เสียง I2C ADC RTC หรือ MC3479

ผลนี้เป็น **user-reported basic runtime/serial smoke test** มีสำเนาและ SHA256 ในเอกสารวิจัย ไม่มี build log, serial capture หรือ PCB revision แนบมาด้วย ไม่ถือว่า peripheral recipe ของ v1.3/rev31 ผ่าน iA หรือว่า iP ผ่านทดสอบแล้ว

### อัปเดต 19 ตุลาคม 2026: ผู้ใช้ยืนยันจอ iP เลื่อน A–Z ผ่าน

ผู้ใช้ส่ง source เต็มและยืนยันว่าใช้งานบน **KidBright32iP ผ่าน** เก็บโค้ดเดิมที่ `sensor_examples/kidbright32ip_matrix_az_user_passed.c` เป็นหลักฐาน **user-reported physical LED Matrix pass** สำหรับบอร์ดที่ผู้ใช้ทดสอบ ไม่ใช่ผลทดสอบฮาร์ดแวร์ที่ agent รันเอง และยังไม่ทราบ PCB revision / SDK version / build log

โค้ดใช้ I2C_NUM_0, SDA21, SCL22, address 0x70 ที่ 100 kHz; init 0x21 / 0x81 / 0xEF; ส่ง pointer 0x00 พร้อม RAM 16 ไบต์สลับซ้าย/ขวา; font A–Z แบบ column-major 5×7 ผ่าน `reverse_bits()`; เลื่อนขวาไปซ้ายทุก 80 ms และวนซ้ำ ใช้ `driver/i2c.h` ตระกูล legacy ตลอดโปรแกรม

สำหรับงานจอ iP นี้ ให้ใช้ source ที่ผู้ใช้ทดสอบเป็นจุดเริ่มต้นโดยรักษา font, bit reversal, การสลับ byte และทิศเลื่อน ไม่ต้องถาม revision/รหัสเซนเซอร์อื่นซ้ำ และไม่เปลี่ยนเป็น new I2C driver โดยไม่มีเหตุผลหรือคำขอ กรณีต้อง port ตาม SDK จริงให้แยกเป็นการเปลี่ยนแปลงที่ตรวจทานได้ ห้ามปน legacy กับ new I2C driver

หลักฐานนี้ยืนยันเฉพาะการแสดง A–Z บน iP ที่ผู้ใช้รายงาน ไม่ยืนยันว่า iA และ iP เหมือนกันทุก peripheral: iP ใช้ phototransistor ส่วน iA ที่เอกสารผู้ผลิตให้มาใช้ LDR/MC3479 และยังต้องรักษาขอบเขตหลักฐานของแต่ละรุ่น การไม่มี accelerometer ไม่เกี่ยวกับโค้ดจอชุดนี้

เครื่องมือ deterministic ยังไม่ประกาศ profile `kidbright32_ia`/`kidbright32_ip` การสร้าง custom ESP-IDF สำหรับสองรุ่นนี้ต้องอ้างพิน/ชิปที่ยืนยันของงานนั้น ไม่เลือก `kidbright32_v13` หรือ `kidbright32_rev31` แทนชื่อบอร์ด และไม่เปลี่ยนผล smoke test ให้เป็นการรับรองทุกบล็อก

## งาน LED Matrix บน iP เมื่อไม่พบ revision บน PCB

ชื่อ `iP` / `KidBright32iP` ที่ผู้ใช้ระบุเพียงพอสำหรับระบุรุ่น ไม่ต้องถามชื่อรุ่นซ้ำ หากไม่มี revision ให้บันทึกว่าไม่ทราบ ห้ามกำหนดว่าเป็น Rev.2021.04.01 โดยอัตโนมัติ วงจรผู้ผลิตที่อ้างท้ายไฟล์ระบุจอแดง 16×8 ขับด้วย HT16K33 และสายจอ SDA0=GPIO21 / SCL0=GPIO22 สำหรับงาน A–Z ให้ใช้ source ที่ผู้ใช้ยืนยันผ่านข้างต้นเป็นจุดเริ่มต้น ส่วนการใช้กับ PCB อื่นยังต้องแยกสมมติฐานและผลทดสอบของบอร์ดนั้น ไม่ขยายผลรายงานนี้เป็นการรับรองทุกรุ่น

การไม่มี deterministic preset ไม่ได้ห้ามสร้างโปรเจกต์ custom: สร้าง workspace ใหม่โดยเว้น `board_profile` และ `reference_example` แล้วเสนอ `main/main.c` และ dependencies ผ่าน Keep/Undo ตามปกติ งานแสดง A–Z เลื่อนจากขวาไปซ้ายไม่ต้องทราบชิปตรวจการเคลื่อนไหว อุณหภูมิ RTC หรือขา S2 จึงไม่ต้องขอภาพหน้า–หลังหรือรหัสเซนเซอร์เหล่านั้น ห้ามเอาปัญหาคนละ peripheral มาขวางงานจอ อ้างผลผ่านจอได้เฉพาะในฐานะผลที่ผู้ใช้รายงานข้างต้น ไม่ใช่การรับรองทุกรุ่นหรือผลที่ agent รันเอง

หากไม่อนุญาต private context ใช้ public SDK reference และ starter ที่เครื่องมือสร้างคืนมาเพื่อเสนอร่างได้ โดยไม่อ่านไฟล์/พาธส่วนตัว ไม่อ้าง SDK ที่ติดตั้งว่าได้รับการตรวจแล้ว และรอผู้ใช้ Keep กับการอนุญาต Build ก่อนตรวจ compilation จริง
